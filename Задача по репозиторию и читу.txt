2. Требования к детализации функций







Для каждой функции ты должен определить:







· Название (отображаемое в меню)



· Тип (Toggle, Slider, Combo, Button, Color Picker, Keybind, Multi-Select)



· Категорию/подкатегорию



· Описание (что делает)



· Параметры:



  · Для Toggle: только состояние (вкл/выкл), но может иметь дополнительные зависимые настройки.



  · Для Slider: мин, макс, шаг, значение по умолчанию, единицы измерения.



  · Для Combo: список доступных опций с пояснениями.



  · Для Keybind: режим (Toggle, Hold, Always), поддерживаемые клавиши.



  · Для Color Picker: RGB/HSL, альфа.



· Зависимости: какие другие настройки должны быть включены/выключены для активации этой функции.



· Примечания по безопасности (Legit vs HVH): должна ли функция автоматически отключаться в Legit-режиме для предотвращения бана.

5. Инструкция по реализации







После предоставления полного списка функций, ты должен:







· Для каждой функции создать соответствующий элемент интерфейса в ImGui, используя единую систему конфигурации.



· Реализовать логику работы функции в отдельных классах/модулях, избегая дублирования кода.



· Обеспечить сохранение/загрузку всех настроек в JSON-файл через систему профилей.



· Добавить поддержку горячих клавиш, включая возможность задания комбинаций и режимов (Toggle, Hold).



· Для всех визуальных элементов (ESP, Chams и т.д.) использовать кэширование и обновление только при изменении данных, минимизируя нагрузку на FPS.



· Внедрить систему условной активации: многие функции должны автоматически отключаться/включаться в зависимости от состояния игры (например, AA отключается при дефьюзе).



· Для HVH-функций предусмотреть автоматическое отключение при игре на официальных серверах (определять по наличию VAC или по консольной переменной).







6. Требования к коду







· Язык: C++17 (или выше), с элементами метапрограммирования для автоматической генерации UI из структур конфига.



· Все строки, связанные с читом, должны быть зашифрованы (compile-time XOR или более сложное).



· Интерфейс: ImGui с кастомным стилем, вкладки, подменю, поиск по настройкам.



· Производительность: использовать многопоточность для нетчаннела и загрузки скинов, но синхронизировать с игровым потоком через мьютексы.

Инструкции по интеграции и расширению:







1. Система конфигурации: создать класс ConfigManager, который рекурсивно обходит эту структуру, создавая JSON-файл профиля. При запуске считывать настройки из профиля и применять к переменным.



2. Генерация GUI: написать функцию RenderMenu(), которая динамически создает ImGui-элементы согласно метаданным (Toggle → Checkbox, Slider → SliderInt, Combo → Combo, и т.д.). Использовать библиотеку imgui и вкладки для разделов. Для вложенных подменю использовать TreeNode или отдельные окна.



3. Производительность: обновлять ESP и другие визуальные элементы только при необходимости, кэшируя результаты WorldToScreen. Для HVH-функций обеспечить минимальную задержку, используя прямой доступ к памяти.



4. Безопасность: для HVH-функций ввести проверку if(!g_LocalPlayer-&gt;IsOnOfficialServer()). Для скрытности использовать шифрование строк (макрос ENC(str)) и очистку PE-заголовков.



5. Горячие клавиши: все Keybind должны поддерживать режимы Toggle/Hold/Always. Реализовать через класс KeybindManager, обрабатывающий WndProc.



6. Зависимости: каждая функция с dependency должна автоматически скрываться/отключаться в GUI и в коде, если родительская функция не активна или условие не выполнено.
